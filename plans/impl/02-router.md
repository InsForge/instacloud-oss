# 02 WP2: router (hostnames, lanes, hold-and-wake, custom domains, ask endpoint)

Contract: `00-contract.md` sections 3 (`lanes`, `tls`), 7.1 (WP2), 8.1, 8.2, 9 (WP2 rows), 10, 11, 13. Design source: `designs/wp2.json`, adjusted to decisions 3 to 7, 21, 22, 25, 26, 42 (upstream discovery moved to WP3's `src/upstream.ts`; the router consumes it). Merge position: after WP3.

## Scope

- `src/router/`: one HTTP lane (Host routing, WebSocket passthrough, hold-and-wake, X-Forwarded-*, post-wake readiness retry, activity ticker), a Postgres wire lane (SSLRequest answer, TLS termination, SNI routing, wire readiness probe, splice), TLS-SNI lanes for redis and mongo (server mode), plaintext per-port lanes (local mode every database; server mode MySQL), a route table rebuilt from state on `rev` change, certificate loading from Caddy's store with issuance trigger, the loopback `ask` listener, custom-domain routes.
- Engine seams: hostnames, lane addresses, `serviceUrl` before deploy, `containerize`, `--add-host` aliases, local host-port allocation, host-free assertions, custom-domain CRUD, `ownsHostname`, `rowNetwork`.
- `main.ts` wiring through `serverFactory`; router owns the primary `node:http` server and any extra listeners.

Depends on landed: `src/upstream.ts` (WP3) for `resolve/forget/dial`; `engine.touch/wake/stateOf` (WP3); registrations and `services()` skeleton (WP5). No new dependency.

## Algorithm

### 0. Listeners per mode (`main.ts` region WP2 + `router/index.ts`)

- In `main.ts` region `WP2 (router)` (after the engine, before `buildServer`, contract 1.1): `router = new Router({ cfg, table, stateOf, wake, touch, beginHold, endHold, upstream })` where `upstream` is the ONE `Upstream` instance main.ts constructed in region `WP3 (upstream)` (shared with `DockerRuntime` and the scheduler, decision 57) and `apiHandler` is NOT passed (it arrives through `attach`); `engine.router = router` (the engine's `router.invalidate()` calls now reach it); `buildServer(engine, cfg, { serverFactory: (handler) => { router.attach(handler); return router.httpServer } })`; `await app.listen({ host: cfg.listenHost, port: cfg.port })`; in region `WP2 (start)`: `await router.start()`.
- `router.start()`: for each `cfg.extraListenHosts` create another `http.Server` with the same `request`/`upgrade` handlers and listen on `<host>:<port>` (local Linux bridge gateway); bind lanes: server mode pg `LANE_BIND:5432`, redis SNI `:6379`, mongo SNI `:27017`, one plaintext lane per MySQL service on its `branch.lanes[id]`; local mode one plaintext lane per database service on `127.0.0.1:<lanePort>` (+ bridge gateway on Linux), pg goes through `pg.ts` on those ports too; server mode also starts `internal.ts` on `127.0.0.1:<internalPort>`. A FIXED lane port in use (5432/6379/27017/internal) aborts startup naming the port. A per-service lane port in use (`branch.lanes[id]`, something else grabbed 20000-20999 on a laptop) logs a warning and reallocates that service's lane through `allocLanePort()` (bind-probed), updating `branch.lanes[id]` in one `mutate` and rebuilding the table; startup aborts only when the range is exhausted.
- `table()`: `if (cached && cached.rev === stateRev()) return cached.table; rebuild` (`stateRev()` is WP1's clone-free read; `loadState()` is called only inside the rebuild). `invalidate()` rebuilds the table NOW and reconciles lane listeners synchronously (add missing, close removed), so a route added by `services add postgres` listens before any request arrives; the router also subscribes to `state.onSave` for routing-class saves as a belt. The engine calls `router.invalidate()` after every `mutate` that changes hosts or lanes: `provisionBranch`, `addDbService`, `addStorageService`, `addManagedService`, `addComputeService`, every rename and remove, domain CRUD, `destroyBranch`, `destroyProject` (05 §3 lists them). Audit-class saves (`emit`, `touchLater`, `markSlept`) bump `auditRev` only and never rebuild the table (decision 54).
- Request dispatch (decision 4): `host = hostOnly(req.headers.host)`; `isDaemonHost(cfg, host)` -> `apiHandler`; else `table().byHost(host)` -> the HTTP lane (minted names and custom-domain aliases in both modes); else server mode -> 404 `{error:'unknown route'}`, LOCAL mode -> `apiHandler` (today's behaviour: any other Host on the daemon's own port is the API, so a LAN name or `host.docker.internal:8080` from a container works, while a local-mode custom domain still routes through its alias because the table lookup comes first).
- `router.stop()`: close listeners, destroy every lane socket, answer requests still waiting on a wake with 503 `{error:'daemon shutting down'}` (pg: ErrorResponse 57P03); called FIRST on SIGTERM (01 §1.8) so `app.close()` never waits on a held wake or a splice.

### 1. Hostnames (`table.ts`)

`labelFor(kind, name, ref)` returns the bare label: compute `${name}-${ref}` (name = group; `default` literal), postgres `pg-${name}-${ref}`, managed `${type}-${name}-${ref}`. Bound (decision 55): when the label exceeds 63 chars (a cloud-legal 39-char name plus a 41-char ref reaches 84), `label = readable.slice(0, 56) + '-' + sha256(readable).slice(0, 6)` (strip a trailing `-` from the slice first); deterministic and unique, never a 400. `hostFor(kind, name, ref, domain)` = `${labelFor(...)}.${domain}` (the FQDN); the engine's `hostFor(kind, name, ref)` passes `cfg.domain` and its `assertHostFree` takes the LABEL. The minted host is written on the row at provision/deploy (`apps[g].host`, `databases[id].host`, `managed[id].host`) and every later read (`buildTable`, `laneAddress`, `serviceUrl`, `rowNetwork`, `hostAliasesFor`) takes it from the row; `hostFor` runs only when the row has none (legacy rows). Static hosts `api.`, `console.` (both modes) and, in SERVER mode only, `s3.`, `*.s3.` (bucket vhosts, kind `garage-vhost`; upstream chosen per request, §3.1; local mode keeps Garage's own `.web.garage.localhost:3902` public URLs, decision 20). Reserved labels `api|console|s3`. `assertHostLabel` (`^[a-z0-9]([a-z0-9-]{0,61}[a-z0-9])?$` per label, FQDN <= 253) applies ONLY to operator-supplied custom-domain hostnames (400). Engine `assertHostFree(label)`: label not in `buildTable(state).hosts()` and not in a pending reservation; runs inside the same synchronous `mutate` that pushes the registration or reserves the lanes (decision 51), under the engine-wide `serialize('provision')` chain; called from `provisionBranch` (every label the new branch will mint), `addComputeService`, `addDbService`, `addManagedService`, `addStorageService` (bucket vhost `io-<ref>-<name>`), and the renames.

### 2. Table build

For each branch b of project p: routes for every `apps[group]` (`key ${b.id}:cp-${g}`, lane http, container `io-<ref>-app-<g>`, port `app.port`, host `app.host ?? hostFor(...)`, `desiredState: app.desiredState ?? 'running'` copied at build time, aliases = custom domains bound to `(b.id, g)`); every `databases[id]` (lane `pg`, container from state, port 5432, `listenPort` = local `b.lanes[id]` else `cfg.lanes.pgPort`, `tls` = server, `desiredState: 'running'`); every managed service with `b.managed[id]` (lane `sni` when server and `MANAGED_DB[type].sni`, else `port`; `listenPort` = sni ? catalog port : `b.lanes[id]`). Static: `api`, `console` (kind `api`) in both modes; server mode only (decision 20): `s3.<domain>` (kind `garage`, upstream 127.0.0.1:3900), `*.s3.<domain>` (kind `garage-vhost`: two upstreams, 127.0.0.1:3900 for signed or non-GET traffic and 127.0.0.1:3902 for anonymous GET/HEAD, decided per request in §3.1). `buildTable` NEVER throws (it runs on the request path): a duplicate host or lane port is logged once per rebuild and the first route wins (decision 51); the engine's reservations make duplicates impossible from now on, legacy state may still carry them.

### 3. HTTP lane (`http.ts`)

1. Route by host (the dispatcher in §0 already sent daemon hosts and, in local mode, unknown hosts to `apiHandler`); none -> 404 `{error:'unknown route'}`; `garage` (server mode) -> proxy to 127.0.0.1:3900 (no wake, no stamp); `garage-vhost` (`<bucket>.s3.<domain>`, server mode) -> pick the upstream PER REQUEST: `Authorization` starting `AWS4-HMAC-SHA256`, or `X-Amz-Signature`/`X-Amz-Algorithm` in the query, or any method other than GET/HEAD -> the S3 API 127.0.0.1:3900 (SDKs default to virtual-hosted addressing, so signed PUT/GET/LIST from apps arrive here; Garage's `root_domain` accepts the vhost); otherwise -> the web endpoint 127.0.0.1:3902 (anonymous reads of public buckets). Non-compute -> 503 `{error:'this service serves no HTTP endpoint'}`.
2. `route.desiredState` (copied at table build, no state read): `stopped` -> 503 `{error:'service is stopped'}`; `suspended` -> 503 `{error:'service is suspended'}`.
3. `touch(route.key)`; `beginHold(route.key)` and `endHold` when `res` (or the upgraded socket) closes. ONE shared `setInterval(touchDebounceMs)` in the router walks the held-key counts and touches every key with a count > 0 (a thousand SSE clients cost one timer, not a thousand); the counts are also the scheduler's `holds(key)` eviction guard.
4. `up = await upstream.resolve(container, network, port)`; when null or `stateOf(route) !== 'running'`: `woke = true; await deps.wake(route)` directly (the scheduler is singleflight per key and bounded by `wakeTimeoutSec`; the router keeps no second map or timer); then re-resolve; `probePort(up, probeWindowMs)`. The router never takes the per-key operation lock; `deps.wake` does (decision 52), so a request that lands mid-deploy, mid-lifecycle or mid-stop waits behind that op inside `wake` and is then proxied to whatever container the op left (hence re-resolve AFTER the wake, never before: the deploy may have replaced the container). `stateOf` reports `asleep` while a stop is in flight, so the lane always takes this path instead of dialling a stopping container. Errors: `WakeTimeoutError` -> 504 `{error:'service wake timed out'}`; `ServiceStoppedError` -> 503 `{error:'service is stopped'}`; `NoContainerError` -> 503 `{error:'service has no container (deploy in progress or removed)'}`; other -> 503 `{error:'service could not be woken'}`; client aborted -> stop. The total hold is `wakeTimeoutSec` (60 s) plus up to `probeWindowMs + readyWindowMs` (38 s) of readiness retries; the docs state both numbers.
5. Proxy with `http.request` (keep-alive agent, maxSockets 256): drop hop-by-hop headers, keep `Host` as sent, append `X-Forwarded-For`, set `X-Forwarded-Proto` (`https` when the request came from the edge over loopback with that header, else `http`), `X-Forwarded-Host`. Stream both ways; on `ECONNREFUSED|EHOSTUNREACH|ETIMEDOUT` `upstream.forget(container)`; on a cache hit that refuses, re-resolve once and take the wake path within the same request (bounded to one retry).
6. Post-wake readiness retry (only when `woke`): bodiless idempotent GET/HEAD/OPTIONS retry 502/503/504 within `readyWindowMs` (200 ms doubling to 1 s, jitter); bodied requests wait on `HEAD /` until non-5xx then forward exactly once.
7. Upgrade: after 4, `net.connect` to the upstream, write the request head, `splice(clientSocket, up, { idleMs: 0, onBytes: noop })`; the hold (and so the shared ticker) stays until close.

### 4. Postgres lane (`pg.ts`)

Per connection: read 8 bytes as `head` (10 s timeout); classify: `0x16` direct TLS (PG17 `sslnegotiation=direct`); `80877103` SSLRequest; `80877104` GSSENCRequest (answer `N`, loop); StartupMessage 3.0. Server mode: SSLRequest -> write `S`, then `new tls.TLSSocket(c, { isServer: true, secureContext: defaultContext, SNICallback })`; direct TLS -> `c.unshift(head)` FIRST (those 8 bytes are the start of the ClientHello) then the same TLSSocket wrap; route by SNI (`byHost`), unknown -> ErrorResponse `08P01` `no database at this hostname (SNI)`; `servername` empty after the handshake (libpq before 14, older JDBC/ODBC drivers send no SNI) -> ErrorResponse `08P01` `no SNI in the TLS handshake: use libpq 14+ or a driver that sends the hostname (sslsni)` and end; plaintext Startup first -> ErrorResponse `08P01` `SSL is required: add sslmode=require to your connection string`. `defaultContext = certFor('api.' + cfg.domain)` (Caddy issues it at install time; the installer's `curl https://api.<domain>/healthz` guarantees it exists) so a client without SNI completes the handshake and RECEIVES the ErrorResponse instead of an opaque `handshake failure`. Local mode: SSLRequest -> `N`, route by `c.localPort` via `byPort`; a plaintext Startup keeps `head` as pending bytes forwarded to the upstream after the probe. Then: `touch` once; `beginHold`/`endHold` around the connection; resolve/wake exactly as the HTTP lane step 4 (`deps.wake(route)` directly; ErrorResponse `57P03` `the database is waking up; retry` on `WakeTimeoutError`, `08006` for `NoContainerError`); `probePg` (TCP connect, SSLRequest, Startup `{user:'postgres', database:'postgres'}`, first byte `R` = ready, `E` with `57P03`/`starting up` = retry 250 ms, other `E` = ready); connect upstream, forward any buffered Startup bytes, `splice(client, up, { idleMs: laneIdleSec*1000, onBytes: () => touch(key) })`. ErrorResponse encoding: `E` + len + `S FATAL`, `V FATAL`, `C <sqlstate>`, `M <message>`, terminator.

### 5. SNI lanes (`tls.ts`, server mode)

`tls.createServer({ secureContext: defaultContext, SNICallback, minVersion: 'TLSv1.2' })` on 6379 and 27017 (same default context as §4 so a no-SNI client gets a clean close after the handshake instead of an alert); route by servername; empty or wrong lane -> destroy after the handshake; touch once; hold; wake/resolve; readiness redis `PING` -> `+`/`-NOAUTH`/`-WRONGPASS` ready, `-LOADING` retry; mongo `probePort`; splice with touch.

### 6. Port lanes (`port.ts`)

One `net.createServer` per `lane === 'port'` route on `<bind>:<listenPort>`; `c.pause()` until the upstream connects (MySQL greets first); wake/resolve; `probePort`; splice with touch.

### 7. splice (`splice.ts`)

Both directions with backpressure (`pause` on `write() === false`, resume on `drain`), `end` propagation with a 2 s drain then destroy both, `onBytes()` on every non-empty chunk, idle cut when neither direction moved for `idleMs` (checked every `min(idleMs, 30 s)`), `idleMs: 0` disables the cut.

### 8. Certificates (`certs.ts`, server mode)

`new Certs({ certDir, issue })` with `issue: (host) => Promise<void>` injectable; production `issue = triggerIssuance` = `tls.connect({ host: '127.0.0.1', port: cfg.tls.edgePort, servername: host, rejectUnauthorized: false })` with a 15 s bound; tests pass a no-op issuer and point `certDir` at `test/fixtures` (the `router.test` cert laid out as `local/router.test/router.test.crt|.key`). `certFor(host)`: walk `certDir` (Caddy layout `<issuer>/<host>/<host>.crt|.key`), cache by mtime, exact host match; missing -> `await issue(host)` then re-walk. Still missing -> for an SNI name: the lane falls back to `defaultContext` (`certFor('api.' + cfg.domain)`, always present after install) so the client completes the handshake and gets the lane's ErrorResponse / close with a logged warning (never a home-made self-signed cert; decision 21). `SNICallback = (name, cb) => certFor(name).then((ctx) => cb(null, ctx ?? defaultContext), (e) => cb(e))`.

### 9. Internal listener (`internal.ts`, server mode)

`node:http` on `127.0.0.1:<internalPort>`. `GET /tls/ask?domain=X`: `hostOnly(X)`; malformed -> 400; `engine.ownsHostname(h)` -> 200 `ok`; else 404. `GET /healthz` -> 200 `{ok:true}`. Everything else 404. Never logs the domain at info level. `ownsHostname` = `table().hosts()` membership plus `<bucket>.s3.<domain>` for an existing bucket.

### 10. Custom domains (`domains.ts` + `server.ts` region B)

`normalizeHostname` (trim, lowercase, strip trailing dot, validate labels, refuse IP literals and anything under `.${cfg.domain}`). `setComputeDomain(projectId, { hostname, branch?, group? })`: branch defaults to the default branch; group = `body.group` or the sole compute group (400 `group required` otherwise); the group must have an app on that branch (404 `no compute deployed`); bound to another `(branchId, group)` -> 409 `{error: '<h> is already attached to <group>; ...'}`; same target -> idempotent; write `state.customDomains[h]`; `router.invalidate()`. Status (decision 25; the CLI renderer `compute.ts:98-228` is the contract): `dns = [{type:'CNAME', name: h, value: `api.${domain}`, note: publicIp ? `or an A record to ${publicIp}` : undefined, status}]` with `status` in the cloud's `DnsRecordCheck` set only: `ok` when `dns.promises.resolve4(h)` (or CNAME) lands on `resolve4(api.<domain>)` or `publicIp`; `missing` when the name does not resolve (never `pending`, which the CLI renders as `unchecked` plus a blocker); `mismatch` when it resolves elsewhere; `unchecked` when the lookup itself failed. `configured` = `dns[0].status === 'ok'` AND (server mode) `certFor(h)` found; `status` = `ready` when configured else `pending`. NO `ssl`, `origin`, `edgeOrigin`, `originOk`, `originStatus` key in either mode (an `ssl` key makes the CLI treat the answer as plane-shaped, demand `origin` and an ownership TXT, and print `UNCONFIRMED`; only `ssl === 'active'` would read as issued anyway). `flyApp: io-<ref>-app-<group>`; `service: group`; `region: 'local'`. `computeDomainStatus` unbound -> `{hostname, flyApp, configured:false, status:'not added', dns:[], service, region}`. With this envelope `insta compute check-domain` prints `certificate active (edge TLS issued)` and `serving https://<h>` once `configured` is true, and `cname pending / add CNAME ...` before. `listComputeDomains` filters by project (and branch/group). `removeComputeDomain` 404 when not bound. `releaseDomainsFor` called from `destroyBranch`, `destroyProject`, `removeComputeService`, `renameComputeService` (moves entries). Gates: POST/DELETE `deploy`; GETs ungated. Routes: `POST/GET/DELETE /projects/:id/compute/domain`, `GET /projects/:id/compute/domains`.

### 11. Engine seams (region WP2)

`laneAddress(project, branch, sid)` (`sid` is the BARE serviceId: routes strip a `<branchId>:` qualifier through WP5's `resolveSid` before reaching any engine seam, decision 49; router keys stay `${branchId}:${serviceId}` and are never sent to clients): postgres server `<databases[sid].host>:5432 tls` (the recorded bounded label, `pg-<name>-<ref>.<domain>` when short enough), local `127.0.0.1:<lanes[sid]>`; redis/mongo server `<managed[sid].host>:6379|27017 tls`; mysql server `<host>:<lanes[sid]>`; all local `127.0.0.1:<lanes[sid]>`. `serviceUrl(project, branch, group)`: `host = apps[group].host ?? hostFor('compute', group, ref)` (an FQDN, `<label>.<domain>`, so `<label>.localhost` in local mode); server `https://<host>`, local `http://<host>:<cfg.port>`. `allocLanes(project, branchId, ids)` (decision 51): local mode every database id, server mode mysql ids; runs under the engine's `serialize('provision')` chain inside ONE synchronous `mutate`: for each id `allocLanePort()` = the lowest port in `cfg.lanes.portRange` that is absent from every `branch.lanes`, absent from `state.laneReservations`, and passes a bind probe (`net.createServer().listen(port, cfg.lanes.bind)` then close; busy ports are skipped, not fatal), then `state.laneReservations[port] = branchId`; `releaseLanes(branchId)` drops the reservations on compensation, and the branch row's `lanes` supersedes them when written. Two concurrent `branch create` calls on two projects therefore never share a port. `containerize(env)`: local mode replaces `127.0.0.1` host in URL-shaped and `*_HOST` values with `host.docker.internal`; server identity. `hostAliasesFor(project, branch)`: server mode = every FQDN minted on the branch + `api.<domain>` + `s3.<domain>` + `<bucket>.s3.<domain>` for every bucket of the branch + its groups' custom domains + `host.docker.internal` (apps receive `AWS_ENDPOINT_URL_S3=https://s3.<domain>` and agent templates call `https://api.<domain>`; on the e2e's `127-0-0-1.sslip.io` those names resolve to the container itself and on NAT'd or private boxes to an unreachable address, so they must be pinned to `host-gateway` like the service names); local mode = minted FQDNs + `host.docker.internal`. `localHostPort(branch, group, opts)`: local mode today's allocator (`freeHostPorts`, loopback-bound), server `undefined`. `rowNetwork(project, branch, row)`: compute `domain` = bare host, `endpoint` = `host[:port]`; postgres/managed `domain` = lane host, `endpoint` = `host:port`; storage `endpoint` = `s3.<domain>/<bucket>` (server) or today's form (local). DSNs: `credentials`/`secrets`/`envFor` rewrite the stored container-host URL's `host:port` to `laneAddress` and append `?sslmode=require` in server mode; managed bundles use `bundle(laneHost, lanePort, pw, tls)` (`rediss://`, `&tls=true`).

## Docs facts for WP8

- Hostnames: compute `<group>-<project>-<branch>.<domain>`, postgres `pg-<name>-<project>-<branch>.<domain>:5432`, redis `redis-<name>-...:6379`, mongodb `mongodb-<name>-...:27017`, mysql `mysql-<name>-...:<port>` (plaintext, per-service port), `api.`, `console.`, `s3.`, `<bucket>.s3.`.
- Local mode: names end in `.localhost` on port 8080; DSNs use `127.0.0.1:<port>` because containers and Linux hosts without systemd-resolved do not resolve `*.localhost` (macOS and browsers do); inside containers the daemon rewrites to `host.docker.internal`. The `/etc/hosts` fallback is for Linux hosts without systemd-resolved (the e2e `ensure_host` helper does it).
- Hostname labels are capped at 63 characters: a long service name beside a long project/branch pair is shortened to a readable prefix plus a 6-character hash, shown as-is by `insta services list`.
- Server mode DSN `postgres://...@pg-<name>-<ref>.<domain>:5432/app?sslmode=require`; the lane routes by SNI, so the client must send the hostname in the TLS handshake: libpq 14+ (`sslsni` default on), JDBC 42.2.x+, node-postgres, psycopg 3; an older client gets a clear `no SNI in the TLS handshake` error. A client that verifies certificates needs the CA (`INSTA_OSS_CA_FILE`) when the box uses the internal issuer.
- Custom domains: `insta compute set-domain <host> [--group <g>] [--branch <b>]`, `insta compute check-domain <host>`, `insta compute remove-domain <host>`; CNAME to `api.<domain>` (or an A record to the box IP); the edge issues on first request; `check-domain` prints `serving https://<host>` once the record resolves and the certificate exists (server mode) or the record resolves (local mode).
- Buckets: `AWS_ENDPOINT_URL_S3=https://s3.<domain>` works with path-style AND virtual-hosted clients (`<bucket>.s3.<domain>`); anonymous reads of a public bucket use the same `<bucket>.s3.<domain>` name.
- A held request waits up to 60 s for the wake plus up to 38 s of readiness retries (`INSTA_OSS_WAKE_TIMEOUT_SEC`, `INSTA_OSS_PROBE_WINDOW_MS`, `INSTA_OSS_READY_WINDOW_MS`). A silent database connection is cut after 15 minutes (`INSTA_OSS_LANE_IDLE_SEC`); a held HTTP request or WebSocket keeps the service awake.
- The daemon container runs in the host network namespace; apps reach the router via `--add-host` entries the daemon injects (service names, `api.`, `s3.`, bucket vhosts), so the host firewall must allow docker bridge traffic to the host's 443, 5432, 6379, 27017 and the lane range 20000-20999; the installer adds these rules for ufw and firewalld (06 §E.3b); a custom firewall must replicate them.
