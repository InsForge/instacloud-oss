InstaCloud is young and some things are not here yet. Below are the ones people run into most often. If something is blocking you and it is not here, say so on [Discord](https://discord.com/invite/MPxwj5xVvW).

## Sleep is one dial per service

A service either scales to zero or it does not, with no schedule behind the dial and no per-route rule. Compute on your default branch is always-on, compute on every other branch sleeps, and Postgres sleeps everywhere until `insta db always-on on`.

## Background work stops with the machine

Nothing wakes a sleeping service on a timer. A scheduler or queue worker inside your container keeps time while the machine is up and stops dead when it suspends, so the job does not run late, it does not run at all. For anything expressible as SQL, `pg_cron` is the sturdier home, with `insta db always-on on` so the database is awake to fire it.

## Volumes pin a service to one machine

Attach a `/data` volume and the machine count is fixed at 1, scale-to-zero stops the machine instead of suspending it, and the volume never detaches. It only deletes, taking the data with it. For user uploads a [storage service](/storage/overview) is the better tool.

## No private network

Services reach each other over their public HTTPS URLs. Compute listens on one HTTP port with no raw TCP, so a container speaking a wire protocol of its own runs fine and nothing else can reach it. Use the managed Postgres, Redis, MySQL and MongoDB types for that.

## One region per service

You pick a region when you create a service, and `insta services scale` adds replicas in that same region. Multi-region replication is not here yet.

## No spend cap

`insta usage` and `insta billing` show what you are spending. Nothing stops it at a number you choose.

## A branch clones data, not running code

`insta branch create` forks Postgres and storage copy-on-write, so the branch opens holding the parent's rows and objects. Its compute service has a URL and nothing on it until you `insta deploy`.

## The branch boundary is separation, not authorization

A branch keeps work off `main`, but any command taking `--branch main` still reaches `main` from inside one. If an agent runs commands for you, set policy on the actions that matter.

## Agents get one command at a time

`insta compute exec` runs one-shot commands on a live machine. `insta compute ssh` opens a real shell, but it needs an interactive login and refuses API keys, so an agent cannot use it.
